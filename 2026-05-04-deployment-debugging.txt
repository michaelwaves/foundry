● Summary of the fix:

  Root cause — f"steering=@{steering_yaml}" produced an override like
  steering=@/tmp/.../steering.yaml. Hydra's @ syntax is for package paths in
  overrides (e.g. +group@pkg=name), not file paths, so the entire
  @/tmp/.../steering.yaml got interpreted as the config name within the
  steering/ group → "Could not find steering/@/tmp/.../steering.yaml".

  Fix:
  1. api/worker_steering.py — write the per-job YAML into
  sae/configs/steering/job_<uuid>.yaml, which is already on Hydra's search path.
  2. api/modal_worker.py — pass steering=<stem> (a normal Hydra group
  selection), and unlink the file in the finally block so the package configs
  dir doesn't accumulate stale jobs.

  Note: this assumes sae/configs/steering/ is writable inside the Modal
  container — it is, since Modal images install packages at build time and the
  runtime FS allows writes to site-packages. If you'd rather avoid mutating
  site-packages, the alternative is to +hydra.searchpath=[file://<tmp>] and
  write to <tmp>/steering/<name>.yaml; happy to switch to that if you prefer.
