● Plan written to api/plan.md. Here's the summary:

  What changes:
  - store.py dies → jobs live in Supabase Postgres
  - runner.py shrinks to ~20 lines → fires modal_worker.run_job.spawn() instead
  of a subprocess
  - main.py SSE switches from polling an in-memory list to subscribing to a
  Redis pub/sub channel
  - Output download becomes a redirect to a Supabase Storage signed URL

  New files: modal_worker.py (the GPU function), db.py (Supabase CRUD),
  redis_client.py (pub/sub helpers), scripts/upload_weights.py (one-time weight
  upload to Modal Volume)

  Key design call: RFD3 weights go in a Modal Volume (persistent, fast cold
  start) rather than downloading each invocation. The saffron steer call stays
  the same inside the worker — it just runs programmatically instead of as a
  subprocess.

  Implementation order is in Phase 5 — start with infra provisioning (Supabase
  table, Railway Redis, Modal secrets + volume) before touching any code.
